## YYYY-MM-DD - Exposed Axios Request Credentials in Console Logging
**Vulnerability:** Raw error objects (`err`) from Axios were directly logged using `console.error(err)` in authentication stores (like login and registration). This exposed the original request payload (in `err.config.data`), which included sensitive plaintext passwords, directly into the browser console.
**Learning:** In frontend stores dealing with credentials, standard error logging can act as an unintended information leak. Furthermore, addressing this by omitting the error object entirely requires ES2019 optional catch binding syntax (`catch { ... }`) to avoid strict Oxlint `eslint(no-unused-vars)` errors.
**Prevention:** Always silently handle errors in authentication/registration flows by updating local reactive error state (e.g., `error.value = 'Login failed'`) without forwarding raw `err` objects to `console.error()` or `console.log()`. Retain explicit comments when omitting error bindings for security reasons.
