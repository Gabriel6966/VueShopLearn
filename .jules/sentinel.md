## 2025-02-28 - [Omit Password securely from localStorage Without Mutating]
**Vulnerability:** Raw Axios error objects logged to the console leaked credentials during user sign in / sign up requests.
**Learning:** Using `delete` on a shallow copy of an object causes strict type errors from typescript when properties are not explicitly configured as optional (like `contrasena` missing in some strict forms of `Usuario`), and modifies objects in unexpected ways compared to standard ES6 rest destructing. By simply disabling the explicit ESLint configuration for unused variables while destructing to explicitly discard the sensitive `contrasena`, credential leaks to local storage are mitigated safely while retaining a healthy typescript build.
**Prevention:** Always use rest object destructing to separate out passwords safely when assigning response items to client-level persistent storages. Do not log raw `error` exceptions from catch blocks that wrap Axios client requests, since `error.config.data` dumps the entire plaintext payload to the browser.
