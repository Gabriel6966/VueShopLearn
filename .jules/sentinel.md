## YYYY-MM-DD - Fix sensitive credential leak in error logs
**Vulnerability:** Raw Axios error objects (`err`) were being logged directly to the console (`console.error(err)`) in the `Usuario` store during login and registration actions.
**Learning:** Axios error objects encapsulate the original request payload within `err.config.data`. When an authentication or registration request fails (e.g., due to a network error or incorrect credentials), logging the raw error object inadvertently exposes the request payload—including plaintext passwords submitted by the user—to the browser's developer console, creating a significant risk of credential leakage.
**Prevention:** To prevent exposing sensitive data in error logs, never log raw Axios error objects directly. For store actions handling sensitive form submissions, errors should be caught silently using optional catch bindings (`catch { ... }`) or by extracting non-sensitive fields (`err.message`), and local application error state should be updated instead.
