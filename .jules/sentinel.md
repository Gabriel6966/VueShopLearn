## 2025-02-20 - Prevent Credential Leakage via Axios Error Objects
**Vulnerability:** Raw Axios error objects (`err`) were being logged directly to the console (`console.error(err)`) within authentication catch blocks (e.g., `login` and `registro` in `src/stores/Usuario.ts`). This is dangerous because `err.config.data` contains the original request payload in plaintext, exposing sensitive user credentials like passwords to the browser console.
**Learning:** Logging full HTTP error objects instead of specific error messages is a common pattern that inadvertently exposes sensitive request data, especially during authentication or sensitive form submissions. The mock backend setup in this project requires the frontend to request the full user record and verify plaintext passwords locally, making this exposure particularly risky.
**Prevention:** Always catch authentication or form submission errors silently (e.g., using ES2019 optional catch binding `catch { ... }`) or handle them securely without logging the raw error object. Update local error state (e.g., `error.value`) instead of exposing internal details to prevent credential leaks.
