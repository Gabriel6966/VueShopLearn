## YYYY-MM-DD - [Axios Error Logging Leads to Sensitive Data Exposure]
**Vulnerability:** Raw Axios error objects (`err`) were being logged directly to the console (`console.error(err)`) in authentication functions (`login`, `registro`). When an API request fails, the Axios error object contains the original request configuration and payload within `err.config.data`. For login and registration requests, this means plain text passwords and emails were being leaked directly to the browser console on request failure, accessible to anyone with developer tools open or to potential cross-site scripting (XSS) payloads reading console output.
**Learning:** In client-side Vue applications communicating via Axios, unhandled or raw-logged API errors silently turn into severe data leaks. Standard debugging practices (like generic `console.error`) are hazardous when handling authentication data. Furthermore, utilizing `catch (err)` just to omit logging triggers `eslint(no-unused-vars)`, necessitating the ES2019 optional catch binding (`catch {`) for a clean, secure failure path.
**Prevention:** Never log raw HTTP response/request objects (like those from Axios or Fetch) when the payload contains sensitive information (credentials, PII, tokens). Always silently catch these errors for auth endpoints, updating the local UI state (e.g. `error.value`) without exposing the raw error payload. Use the ES2019 optional catch binding (`catch { ... }`) to cleanly discard the error object without triggering strict linting violations for unused variables.
